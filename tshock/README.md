# CaiBotLite TShock 端插件

把 TShock 服务器接到任意 **OneBot v11** 机器人（自建 nonebot / Lagrange / NapCat / LLOneBot …）。

> 这是 [`CaiBotLitePlugin-nonebot`](https://github.com/zlqd123/CaiBotLitePlugin-nonebot)
> 仓库的一部分。部署步骤、鉴权在哪一边、指令表怎么改，见[根目录 README](../README.md)；
> 机器人侧怎么装见 [`nonebot/`](../nonebot/)。

- 上游作者: Cai（[UnrealMultiple/TShockPlugin](https://github.com/UnrealMultiple/TShockPlugin)）
- 编译只需要 .NET 9 SDK，产物就 `CaiBotLite.dll` + `linq2db.dll` 两个文件

## 部署

把 [`release/`](../release/) 里的 `CaiBotLite.dll` 和 `linq2db.dll` 一起放进
`tshock/ServerPlugins/`，重启服务器。

> ⚠️ **不要**把 `GenerateMap.dll` / `Economics.*.dll` / `ProgressControls.dll` /
> `SixLabors.ImageSharp.dll` / `Jint.dll` / `Acornima.dll` 一起复制进去，
> 会让 TShock 启动即崩（`MissingFieldException: Terraria.Netplay.Disconnect`）。
>
> 本仓库已经把那些第三方集成改成运行期探测，编译产物里不会再有它们。
> 需要某个功能就去 TShock 插件市场单独装那个插件。

## 指令

| 语法                           |      权限      |      说明      |
|------------------------------|:------------:|:------------:|
| /caibotlite(cbl) debug       | caibot.admin |    调试模式开关    |
| /caibotlite(cbl) code	       | caibot.admin |    生成验证码     |
| /caibotlite(cbl) info	       | caibot.admin | 显示CaiBot状态信息 |
| /caibotlite(cbl) unbind	     | caibot.admin |   主动解除群绑定    |
| /caibotlite(cbl) group <群号>	 | caibot.admin |  设置白名单提示群号   |
| /caibotlite(cbl) onebot <子命令> | caibot.admin | 管理OneBot v11连接 |

`/cbl onebot` 子命令: `mode` `channel` `url` `listen` `public` `secret` `id` `group` `exec` `reload`,
不带参数则显示当前全部 OneBot 配置。

`exec` 用来管理**远程执行白名单**(`/cbl onebot exec` 查看, `exec + <指令>` 放行,
`exec - <指令>` 禁止)。远程执行用的是固定超管身份的虚拟玩家, TShock 自身的权限检查
对它无效, **这个白名单是唯一真正拦得住的地方**。默认只放行调时间/停天气与一批只读查询指令。

> **白名单的权威只在本文件这里。** nonebot 侧不维护第二份, 它通过 `plugin_list`
> 响应的 `allowed_commands` 字段来读本列表: 在 `/泰拉 帮助` 里如实显示
> `服务器当前允许远程执行: ...`, 并检查自己公开的那部分是不是本列表的子集。
> 要放行新指令, 游戏里 `/cbl onebot exec + <指令>` 即可, 不用动机器人那边。

### 已下线: 登录裁决与白名单

本 fork 已经**不再让机器人参与玩家登录**:

- 删除了 `ClientUUID` 数据包拦截与 `NetGetData` 钩子, 玩家进服完全走 TShock
  自己的 `/login` `/register` 与 SSC;
- 删除了 `whitelist` / `self_kick` / `shop_buy` / `shop_condition` 四个数据包的处理,
  收到直接忽略;
- 删除了 `白名单开关` 配置项与 `/cbl whitelist` 子命令(旧配置文件里的该键会被忽略,
  下次写配置时自动移除);
- 握手包的 `enable_whitelist` 固定为 `false`。

也就是说: **机器人掉线不会挡住任何人进游戏**, 只会让查询类指令失效。

剩下的功能: 进度 / 在线 / 背包 / 排行 / 插件列表 / 地图 / 远程执行指令。

  "群OpenID": "",                   // 同上

    "OneBot通道": "auto",            // auto = 监听+主动连, 先通先用
    "机器人地址": "",                 // client 模式: ws://127.0.0.1:8080/caibotlite
    "本服监听地址": "http://0.0.0.0:17779/",
    "本服公开地址": "",               // 发送 map/存档时需要, 机器人访问不到本服就留空

## OneBot v11 适配

把 `OneBot.机器人连接方式` 改成 `onebot` 即可脱离官方 CaiBot 服务, 对接任意
OneBot v11 机器人。配套的机器人端实现见 `nonebot_plugin_caibotlite`
(也可自行按下方协议实现)。

```json5
{
  "OneBot": {
    "机器人连接方式": "onebot", // caibot=官方机器人, onebot=OneBot v11
    "OneBot通道": "auto",       // auto=监听+主动连, 先到先得(默认)
    "机器人地址": "",           // 留空=只等机器人连过来; 填了就同时主动连
    "本服监听地址": "http://0.0.0.0:17779/",  // 0.0.0.0 / * / + / 具体IP 都可以
    "本服公开地址": "",         // 机器人访问不到本服时可以留空, map 会走 base64 内联
    "通讯密钥": "",             // 与机器人端一致, 留空自动生成
    "默认回复群号": 991556763,
    "服务器标识": "生存服",
    "附送物品名称": true,
    "附件大小上限": 33554432,
    "内联附件上限": 8388608,
    "附件保留小时": 6,
    "重连间隔": 5,
    "心跳间隔": 60
  }
}
```

### 为什么单独用 17779, 不复用游戏端口 / REST API

- **7777 是 Terraria 的游戏协议端口**, 是一条裸 TCP 长连接。要在上面再挂 HTTP/WebSocket
  就必须在前面加一层代理, 那会影响所有玩家的进服, 得不偿失。
- **TShock 的 REST API 就挂在 7777 的 `/v2/` 下**(TSRest), 它是"机器人调用服务器"的
  单次请求接口, 方向正好相反: 白名单校验要求"玩家进服的瞬间由服务器推送事件, 并在这次
  连接里立刻拿到答复"。只用 REST 的话只能让服务器轮询或让机器人长轮询, 既拖慢进服,
  又要多配一个 token, 而且 TSRest 默认是关闭的。
- 所以桥接用**一个完全独立的端口**(默认 17779), 只跑一条 WebSocket 和一个极小的文件
  下载路由。它可以只绑内网网卡、单独做防火墙/端口转发, 不影响 7777, 也不需要额外代理。

### 不同网络 / 只有一端有公网地址时怎么配

两端的 `通道` / `MODE` 是**各自视角**的名字：`client` = 自己是客户端（去连别人），
`server` = 自己是服务端（等别人连），`auto` = 两边身份都试、**先连上的那条生效**，
另一条自动断开。所以只要两端有一台能被另一台访问到，就能配通，不用改代码、
也不用猜自己属于哪种情况。

| 谁能被另一端访问到 | 本服 `OneBot通道` | 机器人端 `CAIBOTLITE__MODE` | 谁去连谁 |
| --- | --- | --- | --- |
| 本服有公网 IP / 域名 | `server`（监听 17779） | `client`（主动连） | 机器人 → 本服 |
| 机器人有公网 IP / 域名 | `client`（主动连） | `server`（监听 8080） | 本服 → 机器人 |
| 不确定 / 两边都行 | `auto` | `auto` | 两条都试, 先通的生效 |
| 两端都没有公网地址 | 任选一端做内网穿透（frp / tailscale / cloudflared），恢复其中一条链路后按上面配 |

判断是否接通: 游戏内 `/cbl onebot` 看"连接状态", 或看控制台的
`[CaiBotLite]已连接 OneBot 机器人: ...`。

> 注意: 发送 map / 存档时用的是**下载链接**, 这个地址必须能被**跑 OneBot 实现的那台机器**
> (Lagrange / NapCat 所在机器)访问到, 也就是本服的 `本服公开地址`。
> 机器人会在请求附件前探测一次: 打不开时它会要求服务器改成 base64 内联发送,
> 地图图片功能不受影响; 存档太大塞不进 QQ 消息, 会提示去检查 `本服公开地址`。

### 桥接协议

通道上流动的每一行都是一个 JSON 信封, 双向通用:

```json
{ "v": 1, "secret": "密钥", "package": "CaiBotLite 数据包(JSON字符串)" }
```

- 本服监听(`auto` / `server` / `http` 通道, 默认 17779)是基于 `TcpListener` 自己实现的
  HTTP + WebSocket, **不依赖 Windows 的 HTTP.SYS, 也不需要管理员权限**, 所以
  `0.0.0.0` / `*` / `+` / `[::]` / 具体 IP 这些写法都能正常绑定, Linux 容器里行为一致。
  开放的路由:
  - `POST /onebot/v11/event` 机器人推送数据包(密钥放在 `Authorization: Bearer xxx` 或信封里)
  - `GET  /onebot/v11/ws` 机器人反向 WebSocket(密钥放在 `?secret=` 或请求头)
  - `GET  /files/{token}/{name}` 下载服务器生成的地图/存档
  - `GET  /health` 健康检查
  - 路由按**后缀**匹配, 所以前面挂了反向代理或带了路径前缀(`本服监听地址` 写成
    `http://0.0.0.0:17779/caibotlite/`)也能命中
  - 认不出来的请求会在控制台打印 `方法 + 路径 + 来源 IP + User-Agent`, 并在响应体里
    列出以上路由, 方便判断是谁在打这个端口(探活、扫描、面板代理等); 它只影响那个请求,
    不会中断桥接连接
- 业务数据包与官方机器人的协议**完全一致**, 仅额外使用两个保留字段:
  - `payload.__bridge`: 本条应答要发回哪个群/QQ, 服务器原样带回
  - `payload.__file`: `{name,url,size,kind}` 附件下载信息(`kind` 为 `image` / `file`)
- 没有 `__file` 但带 `base64` 时, 表示服务器直接把文件内联发过来了
  (本服没有公网地址时的地图图片), 机器人端会按 base64 图片发出去

### 注意事项

- 机器人没连上时, 白名单开启的服务器会拒绝所有玩家进入(与官方机器人的行为一致)
- 物品名称由服务器提供, 机器人端无需内置物品表(可在配置中关闭)
- 地图/存档体积较大, 有公网地址时一律走下载链接, 没有则地图退回内联图片
